# Pokémon Brilliant Diamond ultrawide UI mod

Build tooling for the 3440×1440 ultrawide UI patch for Pokémon Brilliant
Diamond v1.3.0.

## Development

### Requirements

- An x86_64 Linux system with Nix and flakes enabled.
- Your own Pokémon Brilliant Diamond base-game NSP.
- Your own Pokémon Brilliant Diamond v1.3.0 update NSP.
- Your own `prod.keys` capable of decrypting those dumps.
- Enough temporary disk space for both NSPs and the merged extraction.
- ADB only if using the provided Android installation command.

Never commit or distribute game dumps, extracted game files, title keys, or
`prod.keys`. The private inputs and generated directories are Git-ignored.

### Repository layout

| Path | Contents |
| --- | --- |
| `../dumps/` | Shared owned base NSP, update NSP, and `prod.keys` |
| `../extracted/` | Shared merged v1.3.0 ExeFS and RomFS generated by `just extract` |
| `ultrawide-v1.3.0.pchtxt` | Upstream ultrawide patch used by the builder |
| `scripts/` | Maintained UI builder and audit tools |
| `dist/` | The generated, installable mod |

`../dumps/`, `../extracted/`, and `dist/` are ignored by Git. Audits and device
captures are written to unique system temporary directories rather than kept
in the repository.

### 1. Install the dumps and keys

Follow the shared [development setup](../README.md#development) to copy your
base-game NSP, v1.3.0 update NSP, and `prod.keys` into `dumps/` at the repository
root (the parent of `ultrawide/`). Use these exact filenames:

```text
dumps/
├── base.nsp      # Pokémon Brilliant Diamond base game
├── update.nsp    # Pokémon Brilliant Diamond v1.3.0 update
└── prod.keys
```

The build targets:

- Title ID: `0100000011D90000`
- Game version: `1.3.0`
- Build ID: `94CEAE325C205C4B9D6F7235552F28FD`

### 2. Enter the development environment

From the workspace root:

```sh
nix develop
cd ultrawide
uv sync --frozen
```

The Nix shell provides Python, `uv`, ADB, FFmpeg, `just`, `hactool`,
`hactoolnet`, `Il2CppDumper`, and the AArch64 binary tools. Il2CppDumper and
LibHac/hactoolnet are built from source revisions pinned by `../flake.lock`; no
local tool clones are needed.

### 3. Extract and merge the game files

Run:

```sh
just extract
```

This calls the shared `../scripts/extract_game.py` (also available as
`just extract` from the repository root). It validates the three files in
`../dumps/`, identifies the Program NCA inside each NSP, and uses the base NCA
to apply the v1.3.0 RomFS update. Intermediate
files are staged beside the output directory and are deleted when extraction
finishes. The result is:

```text
../extracted/
├── exefs/
└── romfs/
```

Running `just extract` again replaces the existing extraction only after the
new extraction completes successfully.

### 4. Build the mod

```sh
just build
```

The only build output is `dist/`:

```text
dist/
├── exefs/
├── romfs/
├── README.md
└── ui_patch_manifest.json
```

The build already incorporates `ultrawide-v1.3.0.pchtxt`. Do not enable the
upstream ultrawide mod separately.

### 5. Install and configure

Install the built mod into local Eden:

```sh
just install
```

The destination is:

```text
~/.local/share/eden/load/0100000011D90000/[3440x1440 21.9 Complete UI v1.3.0]/
```

Restart the game after installation. The shared installer backs up an existing
copy of this mod in the system temporary directory and preserves other mod
directories.

The optional Android installation command remains available:

```sh
adb devices
just push
```

That replaces the active Eden mod and installs the files under:

```text
/sdcard/Android/data/dev.eden.eden_emulator.nightly/files/load/0100000011D90000/[3440x1440 21.9 Complete UI v1.3.0]/
```

Enable that mod for Pokémon Brilliant Diamond. Configure the emulator to use
its **8 GB RAM layout** and keep **stretch to window** enabled, matching the
upstream patch requirements.

## Development commands

```sh
just audit    # Audit dist/ and write the report to a temporary directory
just capture  # Capture the connected Android screen into a temporary directory
just check    # Syntax-check the maintained Python scripts
```

Each temporary command prints its output path. Copy out anything that must be
retained before the operating system cleans the temporary directory.
